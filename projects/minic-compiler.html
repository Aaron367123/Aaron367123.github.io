01 Overview

After finishing the MIPS emulator, the natural next question was: where does the assembly come from? This compiler answers it. Together, the two projects take a program all the way from C-like source to a simulated CPU executing it.

LexerCharacters → tokens with positions
ParserTokens → syntax tree (AST)
Semantic + optimiseScopes, checks, folding
Codegen → CPUMIPS assembly on my emulator

02 The language

Mini-C is a deliberately small subset of C. It's small enough to finish, but big enough for real programs like recursion, sorting and a prime sieve:

  • 32-bit int only: global variables and arrays, and local variables with block scope and shadowing.
  • Functions with up to 4 parameters, passed in $a0–$a3 following the MIPS convention, plus recursion.
  • if/else, while, for, break, continue, compound assignment (+= and friends), and ++/--.
  • All of C's binary operators with C's precedence, and short-circuit &&/||. Arithmetic wraps at 32 bits.
  • Built-ins print_int, print_char and print("…"), which compile to MIPS system calls.

Errors point at the exact spot with line:col and a caret, like a real compiler. The semantic pass reports every error it finds in one go rather than stopping at the first.

03 Parsing

The parser is hand-written recursive descent. Expressions use precedence climbing: one function handles every binary operator, driven by a precedence table, instead of one grammar rule per precedence level.

src/parser.js
/*
 * parseBinary(minPrec) parses an expression whose binary operators all have
 * precedence >= minPrec. ... The "+ 1" makes operators of equal precedence
 * group to the left:
 *
 *   a - b - c    ->  (a - b) - c
 *   a + b * c    ->  a + (b * c)    (the recursive call swallows "* c")
 */
parseBinary(minPrec) {
  let left = this.parseUnary();
  for (;;) {
    const t = this.peek();
    const prec = t.type === 'op' ? PRECEDENCE[t.value] : undefined;
    if (prec === undefined || prec < minPrec) return left;
    this.next();
    const right = this.parseBinary(prec + 1);
    left = { kind: 'Binary', op: t.value, left, right, ...at(t) };
  }
}

Comment shortened. The prec + 1 in the recursive call is what makes operators left-associative.

04 Code generation

Each function gets a stack frame. The prologue reserves space, saves the return address and the caller's frame pointer, and points $fp at the new frame. The epilogue undoes it in reverse order. Locals and parameters then live at fixed offsets from $fp, which makes recursion work:

src/codegen.js
// Prologue: make the frame, save $ra and the caller's $fp, set up our $fp.
this.emit('addiu', ['$sp', '$sp', String(-frame)], 'prologue: allocate frame');
this.emit('sw', ['$ra', `${frame - 4}($sp)`], 'save return address');
this.emit('sw', ['$fp', `${frame - 8}($sp)`], "save caller's frame pointer");
this.emit('addiu', ['$fp', '$sp', String(frame)], '$fp = top of this frame');
fn.paramSymbols.forEach((symbol, i) => {
  this.emit('sw', [ARG_REGISTERS[i], `${symbol.offset}($fp)`], `parameter ${symbol.name}`);
});

for (const s of fn.body.body) this.statement(s);

// Falling off the end of a function returns 0.
this.emit('li', ['$v0', '0'], 'no return: result is 0');
this.label(`${fn.symbol.label}.ret`);
// Epilogue: the mirror image of the prologue.
this.emit('lw', ['$ra', `${frame - 4}($sp)`], 'epilogue: restore $ra');
this.emit('lw', ['$fp', `${frame - 8}($sp)`], "restore caller's $fp");
this.emit('addiu', ['$sp', '$sp', String(frame)], 'free the frame');
this.emit('jr', ['$ra'], 'return');

Lightly trimmed comments.

Expressions are evaluated into $t registers, which are handed out like a stack. When they run out, or a function call would overwrite them, values are spilled to the memory stack and reloaded afterwards. Every block of output is commented with the source line it came from, which is what lets the demo highlight the matching assembly.

05 Optimising

The -O1 flag turns on two passes:

  • AST optimiser: constant folding (2 * 3 + x → 6 + x), algebraic identities, removal of dead code after return, and strength reduction.
  • Peephole optimiser: scans the generated assembly for wasteful patterns, such as a push immediately followed by a pop, redundant moves, or a jump to the very next line.
src/optimizer.js
// Strength reduction: multiplying by 2^k is a left shift by k (exact
// for 32-bit wrap-around arithmetic, negative numbers included).
if (isPowerOfTwo(rc)) return this.simplified(shiftNode(l, rc, e));
if (isPowerOfTwo(lc)) return this.simplified(shiftNode(r, lc, e));
return e;
case '/':
  if (rc === 1) return this.simplified(l);
  return e; // x / 2^k is NOT x >> k for negative x, so no shift here

That last line avoids a classic trap. In C, -7 / 2 is −3 because division rounds toward zero, but -7 >> 1 is −4 because a shift rounds down. Replacing one with the other would be a bug.

06 Testing

  • Unit tests for the lexer, the parser (precedence, associativity, error messages), the semantic checks and the optimiser.
  • End-to-end: all 10 example programs are compiled at both optimisation levels, run on the real emulator engine, and their output compared exactly.
  • Random programs: 200 randomly generated expressions with literals, locals, globals and function calls, compiled at both levels and checked against an independent 32-bit JavaScript evaluator. A seed makes any failure reproducible. I also ran 5,000 deeper ones locally.
  • A test checks that the browser demo's copies of the compiler and emulator are identical to the source files.

91 tests in total, all passing, and the emulator's own 61 tests still pass too.

07 What I learned

  • Writing a compiler made calling conventions concrete: why $ra must be saved, why the frame pointer exists, and what "caller-saved" really costs.
  • Random-program testing finds the bugs you don't think of, especially around precedence and signed arithmetic.
  • Source-location tracking pays off everywhere: error messages, the assembly comments and the demo's line highlighting all come from it.
  • Next steps: keeping local variables in registers instead of on the stack, constant propagation, pointers and char arrays, and a switch statement.
