Sorting Algorithms

Four classic sorting algorithms written from scratch in Java (selection, insertion, merge and quick sort), each timed on the same random data, plus linear and binary search. Below you can watch them run and benchmark them yourself.

01 Overview

The program fills an array with random integers between 1 and 2,000,000 and makes four identical copies. It sorts each copy into descending order with a different algorithm, timing each one with System.nanoTime(). Because every algorithm gets exactly the same input, the comparison is fair.

It then times linear search against binary search on the sorted array. The binary search is adapted for descending order: when the middle value is smaller than the key, it searches the left half.

Big-O hides constant factors. On very small inputs a simple O(n²) sort can beat merge sort, which is why the benchmark below lets you try several sizes.

04 Quick sort in Java

The quick sort uses the Lomuto partition scheme with the last element as the pivot. Flipping the comparison to arr[j] > pivot is all it takes to sort in descending order:

SortingAlgorithims/ceng318assign1.java
static int partition(int[] arr, int low, int high){
    int pivot = arr[high];
    int i = (low - 1);

    for (int j = low; j <= high - 1; j++) {
        if (arr[j] > pivot) {
            i++;
            swap(arr, i, j);
        }
    }
    swap(arr, i + 1, high);
    return (i + 1);
}

static void quickSort(int[] arr, int low, int high){
    if (low < high){
        int pi = partition(arr, low, high);
        quickSort(arr, low, pi - 1);
        quickSort(arr, pi + 1, high);
    }
}

06 Lessons

  • Benchmark at a meaningful size. With only 50 elements and no warm-up, JVM start-up and JIT compilation take more time than the sorting. Larger arrays, several runs and a warm-up pass give trustworthy numbers.
  • Test search with keys that are present too. The search key (2,500,000) is outside the value range, so both searches always measure the worst case.
  • Watch the loop bounds. The linear search stops at length - 1 and never checks the last element. Off-by-one errors are easy to miss without unit tests.
  • The pivot matters. Always using the last element is fine for random data, but on already-sorted input quick sort drops to O(n²). A random or median-of-three pivot avoids that.
