01 Overview

Digital logic is the layer just above the transistor: everything from an adder to a CPU is built from it. I built this simulator to see that layer move. Most simple simulators compute an answer instantly; this one models time, so you can watch a carry ripple through an adder or see a brief glitch that only exists for one gate delay.

Parts

Switches, buttons, clocks, AND/OR/XOR/NAND/NOR/XNOR (2–4 inputs), NOT, LEDs, probes, a 7-segment display and D flip-flops.

Chips

Package any circuit as a reusable chip, and nest chips inside chips. Recursion is detected.

Analysis

Truth tables (up to 8 inputs), gate count and longest path through the gates.

Sharing

Circuits are compressed into the URL (a 4-bit adder fits in 1,112 characters), or saved as versioned JSON.

02 Event-driven simulation

Re-evaluating every gate on every tick wastes time, because most of a circuit is idle most of the time. Instead, each tick applies only the wire changes scheduled for that moment, and re-evaluates only the gates those wires feed. Each gate's new output is scheduled one tick later in a 16-slot time wheel. This is how real logic simulators scale.

src/simulator.js
// 2. Apply this tick's events; collect the components they feed.
const changed = [];
const dirty = new Set();
for (const [net, v] of bucket) {
  if (this.values[net] === v) continue;
  this._set(net, v, t);
  changed.push(net);
  for (const ci of nets[net].sinks) dirty.add(ci);
}
bucket.clear();

// 3. Evaluate affected components; their outputs land in later buckets.
for (const ci of dirty) this._evaluate(ci, t);
return changed;

Trimmed: the statistics and event-cap bookkeeping are left out.

Because every gate takes one tick, the simulator shows real hardware effects. For example, A AND (NOT A) should always be 0, but when A switches from 0 to 1 the AND gate briefly sees both inputs high and outputs a one-tick spike (a glitch). A test checks for it.

03 Three-valued logic

Real circuits power up in an unknown state. A flip-flop that hasn't been reset could hold either 0 or 1. Every wire here can be 0, 1 or X (unknown), and each gate is defined to give the correct result even when some inputs are unknown:

src/logic.js
/** AND: any 0 forces 0; otherwise any X gives X; otherwise 1. */
export function and(ins) {
  let unknown = false;
  for (const v of ins) {
    if (v === ZERO) return ZERO;
    if (v === X) unknown = true;
  }
  return unknown ? X : ONE;
}

So 0 AND X is 0 (one 0 is enough), but 1 AND X stays X. Unknowns are drawn in red on the board, which makes a missing reset easy to spot.

04 Chips & flattening

The 4-bit adder is built from four full-adder chips, each made of gates. Before simulating, the engine flattens the design: it expands every chip into its gates, and merges each chip's pins with the wires inside it using a union-find structure. Then the simulator only ever sees plain gates and wires.

src/netlist.js
for (const p of iface.inputs) uf.union(`${path}.${p.label}`, `${inner}${p.id}.out`);
for (const p of iface.outputs) uf.union(`${path}.${p.label}`, `${inner}${p.id}.in`);
expand(chip, [chip.chips ?? {}, ...scopes], inner, [...stack, name], false);

The stack of chip names being expanded is how a chip that contains itself is detected and rejected.

05 Catching oscillation

Some circuits never settle. A loop of an odd number of NOT gates (a ring oscillator) flips forever. A naive simulator would just hang. This one works out a bound: in a circuit without loops, every change has finished after at most the sum of all gate delays. If events are still happening long after the last input changed, the circuit must be looping.

src/simulator.js · oscillation
else if (this.pendingEvents > 0 && this.time - this.lastStimulus > this.settleBound) {
  const recent = this._recentNetIdx(this.settleBound);
  const loop = recent.filter((n) => this.loopNets.has(n));
  const involved = loop.length ? loop : recent;
  // Period = gap between the last two rising edges seen after the stimulus.
  let period;
  for (const n of involved) {
    if (this.prevRise[n] > this.lastStimulus) { period = this.lastRise[n] - this.prevRise[n]; break; }
  }
  value = { reason: 'oscillation', nets: involved.map((n) => this.flat.nets[n].name), period };
}

The wires in the loop are found ahead of time with Tarjan's strongly-connected-components algorithm, so the warning can name exactly which wires are oscillating. The 5-stage ring is correctly reported with a period of 10 ticks (5 gates × 2 transitions). A NOR latch released from S = R = 1 shows the classic period-2 race.

06 Measured timing

Because gate delay is modelled, the simulator can measure a known weakness of ripple-carry adders: the carry has to pass through every bit in turn, so the delay grows with the width:

Ripple-carry adderCarry-in → carry-outCritical pathGates
1-bit2 ticks35
2-bit4 ticks510
4-bit8 ticks920
8-bit16 ticks1740

The delay grows linearly: 2 gate delays per bit. That's exactly why real CPUs use carry-lookahead adders, which would make a good next example.

07 What I learned

  • Modelling time changes everything: glitches, races and propagation delay only appear once gates take time to switch.
  • An "unknown" value (X) is honest. It shows uninitialised state instead of hiding it behind a default 0.
  • Graph algorithms show up in unexpected places: union-find for flattening chips and Tarjan's algorithm for finding loops.
  • Limitations and next steps: different rise and fall delays, tri-state buses, setup/hold checks on flip-flops, and component rotation for tidier wiring.
