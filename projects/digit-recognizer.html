Neural Network from Scratch

A neural network written from scratch in plain JavaScript, with no ML libraries. I implemented the matrix maths, backpropagation, the Adam optimiser and data augmentation myself, then trained it on MNIST handwritten digits to 98.86% test accuracy. The same code runs in your browser: draw a digit and watch the network's neurons light up.

01 Overview

Libraries like PyTorch make neural networks a few lines of code, which also hides how they work. I wanted to understand every step, so I built the whole stack myself: matrices, layers, gradients, optimiser, training loop and model format. One codebase trains the network in Node.js and runs it in the browser.

02 The maths, by hand

Each layer has a forward pass and a backward pass that I derived and coded myself. The neatest piece is the output: combining softmax with cross-entropy loss makes the gradient collapse to predicted probability minus the true answer:

src/layers.js · softmax + cross-entropy
/** dL/dz = (p − onehot(label)) / n */
backward() {
  const { n, k, labels } = this;
  const d = this.dBuf.get(n * k);
  const p = this.probs;
  const inv = 1 / n;
  for (let i = 0; i < n; i++) {
    const r = i * k;
    for (let j = 0; j < k; j++) d[r + j] = p[r + j] * inv;
    d[r + labels[i]] -= inv;
  }
  return d;
}

Getting backpropagation slightly wrong is easy, and the network often still half-learns, which hides the bug. So every layer is gradient-checked: the test nudges each weight by ±0.00001, measures how the loss changes, and compares that with the gradient backprop computed. The worst relative error was 9.8 × 10⁻⁹, far inside the 10⁻⁴ tolerance.

The optimiser is Adam with decoupled weight decay (AdamW), also tested against hand-computed steps:

src/optim.js · Adam update
m[i] = b1 * m[i] + (1 - b1) * gi;          // running mean of the gradient
v[i] = b2 * v[i] + (1 - b2) * gi * gi;     // running mean of its square
const mHat = m[i] / bc1;                   // bias correction for early steps
const vHat = v[i] / bc2;
w[i] -= lr * (mHat / (Math.sqrt(vHat) + eps) + (decoupled ? lam * w[i] : 0));

The comments are added here for the case study.

03 Training

  • Network: 784 → 256 → 128 → 10 with ReLU and 20% dropout, 235,146 parameters.
  • Optimiser: AdamW with a learning rate of 0.001, weight decay of 0.02 and batches of 128. The learning rate ramps up over the first epoch (warm-up), then decreases along a cosine curve over 30 epochs.
  • Augmentation I wrote myself: random rotation (±10°), scaling (±5%) and shifts (±2 px), so the network learns digits that aren't perfectly centred.
  • Validation: 5,000 training images are held out, and the best epoch (24) is kept. Training takes about 11 minutes on one CPU core.

The hardest digits are 8 (97.7%), 9 (97.9%) and 5 (98.5%). The most common mistakes are 4→9, 5→3 and 9→4, which are the same pairs humans confuse when writing quickly.

05 Running in the browser

MNIST digits are always centred and scaled the same way, but a person's drawing isn't. Feeding the raw canvas to the network gives poor results, so the demo recreates MNIST's exact preprocessing:

  • Crop to the drawing's bounding box, and adjust the stroke width to match MNIST's pen.
  • Scale the longest side to 20 px, averaging pixels and keeping the aspect ratio.
  • Centre the result in a 28×28 frame by its centre of mass, using a sub-pixel shift.
src/preprocess.js
// --- 4. centre of mass → (14, 14) with a sub-pixel bilinear shift --------
const com = centerOfMass(box, tw, th);
const ox = MNIST_COM - com.x, oy = MNIST_COM - com.y; // where box(0,0) lands in the frame
const input = new Float32Array(FRAME * FRAME);
for (let y = 0; y < FRAME; y++) {
  for (let x = 0; x < FRAME; x++) input[y * FRAME + x] = bilinear(box, tw, th, x - ox, y - oy);
}

06 Making it fast

Pure JavaScript has no GPU and no BLAS library to lean on, so the matrix multiply decides how fast training is. I profiled it, then optimised step by step:

OptimisationSpeed-up vs naive loop
Forward pass, 4×4 register tiling4.1×
+ skipping zero pixels (~81% of MNIST is blank)7.9×
Weight gradient (Xᵀ·G)3.3×
Input gradient (G·Wᵀ)3.8×

Skipping zero pixels only works if the input is never shifted away from zero. So instead of normalising the pixels, I built the normalisation into the first layer's weights and bias (and gradient-checked that change too). Profiling also showed that a sum recomputed on every prediction was the real bottleneck. Caching it cut inference from 0.49 ms to 0.11 ms.

07 What I learned

  • Gradient checking is essential. A network with a subtly wrong gradient still learns a bit, so the bug hides.
  • Preprocessing mattered as much as the model. Matching MNIST's centring is the difference between a toy and a demo that works.
  • 8-bit quantisation cost nothing here and made the download four times smaller.
  • Limitations: there's no "not a digit" answer, so a scribble still gets a confident guess. A small convolutional network (CNN) would typically reach about 99.3–99.5%, which is my next step.
